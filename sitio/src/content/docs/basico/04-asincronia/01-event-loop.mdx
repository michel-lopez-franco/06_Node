## Objetivos

- Distinguir código síncrono de código asíncrono.
- Explicar qué hace el _event loop_ y qué papel tiene libuv.
- Predecir el orden entre código síncrono, microtareas y temporizadores.
- Usar `setTimeout`, `setInterval` y cancelarlos.
- Reconocer código que bloquea el _event loop_.

## Explicación

### Síncrono y asíncrono

El código **síncrono** se ejecuta línea por línea: cada una espera a que termine la anterior.
El código **asíncrono** empieza algo que tarda, deja una función para cuando termine y sigue
de largo sin esperar. `setTimeout(funcion, 100)` es el ejemplo más simple: no se detiene
100 ms, sino que agenda `funcion` y pasa a la siguiente línea.

### Un solo hilo y un ciclo de eventos

Tu JavaScript corre en **un solo hilo**: hace una cosa a la vez. Aun así, un servidor de Node
atiende a miles de usuarios. El truco está en el reparto de trabajo que viste en el módulo 1:

1. Tu código pide algo que tarda (un temporizador, leer un archivo, una consulta a la red).
2. **libuv** se encarga de esperarlo, fuera de tu hilo, y tu código sigue.
3. Cuando la operación termina, su función pendiente se forma en una **cola**.
4. El **_event loop_** (ciclo de eventos) revisa las colas y ejecuta esas funciones, una por
   una, **solo cuando tu código actual terminó**.

Es como una cocina con un solo cocinero: mete el pan al horno, pone un temporizador y, en vez
de quedarse mirando el horno, pica verduras. Cuando suena el temporizador, termina lo que
estaba picando y saca el pan.

### El orden de las cosas

Cuando termina el código síncrono, Node atiende el trabajo pendiente en este orden:

1. **Microtareas:** los `then` de promesas ya cumplidas (lección siguiente) y
   `queueMicrotask`. Se atienden **todas**, en el orden en que se agendaron, antes de pasar
   a lo siguiente.
2. **Tareas del event loop:** temporizadores (`setTimeout`, `setInterval`), respuestas de
   archivos y de red, etc. Después de **cada** una, se vuelven a vaciar las microtareas.

Por eso un `setTimeout(..., 0)` no es "inmediato": espera a que termine el código síncrono y
a que se vacíen las microtareas.

<Aside title="¿Y process.nextTick y setImmediate?">
  Vas a verlos en código de Node: `process.nextTick` agenda algo muy pronto (junto a las
  microtareas) y `setImmediate` justo después de atender la entrada y salida. Su orden exacto
  frente a promesas y temporizadores cambia según el contexto (incluso entre un archivo ESM y
  uno CommonJS), así que no escribas código que dependa de él. En código nuevo, usa promesas.
</Aside>

### Temporizadores

- `setTimeout(funcion, ms)` ejecuta la función **una vez**, al menos `ms` milisegundos
  después (puede ser más si el hilo está ocupado).
- `setInterval(funcion, ms)` la ejecuta **cada** `ms` milisegundos.
- Ambos devuelven un identificador para cancelarlos con `clearTimeout` o `clearInterval`.
- Mientras haya un temporizador o un intervalo activo, el programa **no termina**.

### No bloquees el event loop

Si tu código síncrono tarda, nadie más puede ejecutarse: los temporizadores se retrasan y, en
un servidor, **ningún** usuario recibe respuesta mientras tanto. Los culpables típicos son
ciclos muy largos, cálculos pesados y las versiones síncronas de las APIs de Node (como
`readFileSync`, que verás en el módulo 5). En el módulo 18 verás cómo mover trabajo pesado a
otros hilos.

## Errores comunes

**El programa nunca termina (se queda "colgado" en la terminal).** Quedó un `setInterval`
activo, o un servidor escuchando. Cancela el intervalo con `clearInterval` cuando ya no lo
necesites. Para salir en ese momento, presiona <kbd>Ctrl</kbd> + <kbd>C</kbd>.

**Un valor sale `undefined` porque "todavía no llega".** Usaste afuera un resultado que se
asigna dentro de un callback o un `then`. El código de afuera se ejecuta **antes**. Todo lo
que dependa del resultado tiene que ir dentro del callback (o después de un `await`, en la
lección 3).

**Un temporizador se ejecuta mucho después de lo indicado.** Algo síncrono está ocupando el
hilo. `ms` es un mínimo, no una garantía.

**`TypeError [ERR_INVALID_ARG_TYPE]: The "callback" argument must be of type function.
Received undefined`.** Le pasaste a `setTimeout` el **resultado** de llamar a una función
(`setTimeout(saludar(), 100)`) en lugar de la función (`setTimeout(saludar, 100)` o
`setTimeout(() => saludar('Ana'), 100)`).
