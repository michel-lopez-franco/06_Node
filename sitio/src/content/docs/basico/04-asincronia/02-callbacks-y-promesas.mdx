## Objetivos

- Usar una función con un _callback_ error-first y manejar su error.
- Explicar por qué los callbacks anidados se vuelven difíciles de leer.
- Crear una promesa con `new Promise` y consumirla con `then`, `catch` y `finally`.
- Encadenar promesas y atrapar errores de cualquier paso con un solo `catch`.
- Convertir una función con callback en una que devuelve promesa.

## Explicación

### Callbacks error-first

La primera forma de escribir código asíncrono en Node fue el **_callback_**: una función que
le pasas a otra para que la llame cuando termine. Node adoptó una convención llamada
**error-first** (error primero):

```js
buscarTarea(1, (error, tarea) => { /* ... */ });
```

- El callback siempre recibe **primero el error**: `null` si todo salió bien, o un `Error`.
- Después vienen los resultados, que solo sirven si no hubo error.

Por eso todo callback empieza con `if (error) { ...; return; }`. Si olvidas el `return`, el
código sigue con un resultado `undefined`.

### El problema: callbacks anidados

Si un paso depende del anterior, su código va **dentro** del callback anterior. Con tres o
cuatro pasos, el código avanza hacia la derecha en forma de pirámide y cada nivel repite el
manejo del error. A esto se le llama _callback hell_ (el infierno de los callbacks). Las
promesas nacieron para resolverlo.

### Promesas

Una **promesa** es un objeto que representa un resultado que todavía no está listo. Siempre
está en uno de tres estados:

- **Pendiente** (_pending_): la operación no ha terminado.
- **Cumplida** (_fulfilled_): terminó bien y tiene un **valor**.
- **Rechazada** (_rejected_): falló y tiene un **motivo**, normalmente un `Error`.

Una vez cumplida o rechazada, ya no cambia. Para usar el resultado:

- `promesa.then(valor => ...)` se ejecuta si se cumple.
- `promesa.catch(error => ...)` se ejecuta si se rechaza.
- `promesa.finally(() => ...)` se ejecuta en ambos casos; útil para limpiar.

Para **crear** una promesa, `new Promise` recibe una función con dos parámetros, `resolve` y
`reject`: llama a uno de ellos cuando la operación termine. Casi nunca lo necesitas, salvo
para envolver APIs de callbacks.

### Encadenar

`then` devuelve **una promesa nueva**, así que puedes encadenar pasos:

- Lo que devuelves en un `then` le llega al siguiente.
- Si devuelves una **promesa**, el siguiente `then` espera a que se cumpla.
- Si algún paso falla, se saltan los `then` que siguen hasta el primer `catch`.

El resultado es código plano, un paso por renglón, con un solo lugar para los errores.

### De callbacks a promesas

- **`util.promisify(fn)`** convierte una función error-first en una que devuelve promesa.
- Muchos módulos de Node ya traen su versión con promesas: `node:timers/promises`,
  `node:fs/promises` (módulo 5), `node:dns/promises`... Prefiérelos.

## Errores comunes

**`TypeError: Cannot read properties of undefined (reading 'titulo')` dentro de un
callback.** Hubo un error y lo ignoraste: revisaste `if (error)` pero sin `return`, o no lo
revisaste. Con error, el resultado es `undefined`.

**Un `then` recibe `undefined`.** El `then` anterior no devolvió nada. Si usas llaves en la
función flecha, necesitas `return`: `.then((t) => { return buscarUsuario(t.usuarioId); })`.

**Un `then` recibe `Promise { <pending> }`.** Anidaste un `then` dentro de otro en lugar de
devolver la promesa. Devuélvela y encadena el siguiente `then` afuera.

**La promesa se queda pendiente para siempre.** Dentro de `new Promise` hay un camino que no
llama ni a `resolve` ni a `reject`. Revisa cada `if`.

**`TypeError: Promise resolver undefined is not a function`.** Escribiste `new Promise()` sin
la función con `resolve` y `reject`.
