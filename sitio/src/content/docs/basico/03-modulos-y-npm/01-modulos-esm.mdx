## Objetivos

- Exportar funciones, clases y valores con exportaciones con nombre y por defecto.
- Importar desde tus archivos, desde módulos de Node (`node:`) y desde JSON.
- Explicar por qué un módulo se evalúa una sola vez y qué es un enlace vivo.
- Reunir varios módulos en uno con `export ... from`.
- Resolver los errores `ERR_MODULE_NOT_FOUND` y `does not provide an export named`.

## Explicación

### Un archivo, un módulo

En Node, cada archivo `.js` es un **módulo**: tiene su propio alcance. Una variable o función
que declaras en un archivo **no** existe en los demás, a menos que ese archivo la **exporte**
y el otro la **importe**. Así cada archivo decide qué es público y qué es un detalle interno.

El sistema que usa este curso se llama **ESM** (_ECMAScript Modules_, los módulos estándar de
JavaScript): es el mismo `import`/`export` que usa el navegador. Es el que viste desde el
módulo 0 en `export function` de cada `solucion.js`: ese `export` es lo que deja que el
archivo de tests use tu función.

### Exportar

Hay dos tipos de exportación:

- **Con nombre:** `export` delante de una declaración (`export function sumar`,
  `export const PI_APROX`). Puede haber todas las que quieras. Quien importe debe usar el
  nombre exacto, entre llaves.
- **Por defecto:** `export default` delante de una función, clase o valor. Solo una por
  módulo, y quien la importe le pone el nombre que quiera, sin llaves.

Prefiere las exportaciones con nombre: el editor las autocompleta, los errores de dedo se
detectan al arrancar y todos las llaman igual. La exportación por defecto es útil cuando el
módulo ofrece una sola cosa principal.

### Importar

```js
import areaDeCirculo, { sumar, PI_APROX } from './modulos/matematicas.js';
```

- Las rutas a tus archivos empiezan con `./` o `../` y **llevan la extensión** `.js`. Node no
  la adivina.
- Los módulos de Node se importan con el prefijo `node:` (`node:os`, `node:util`). Así queda
  claro que vienen con Node y no de un paquete instalado.
- Un nombre suelto, sin `./` ni `node:` (`'picocolors'`), es un **paquete** instalado con npm;
  lo ves en la lección 4.
- Los `import` van hasta arriba del archivo. Node los lee **antes** de ejecutar cualquier
  línea: si pides algo que no existe, el programa ni siquiera arranca.

También puedes renombrar al importar (`{ multiplicar as por }`) o juntar todas las
exportaciones en un objeto (`import * as matematicas`).

### Un módulo se evalúa una sola vez

La primera vez que alguien importa un módulo, Node lo ejecuta y guarda el resultado. Las
siguientes veces entrega **el mismo** módulo, sin volver a ejecutarlo. Por eso, si dos
archivos importan un contador, los dos comparten el mismo estado.

Además, lo que importas es un **enlace vivo** (_live binding_): si el módulo original cambia
el valor de una variable exportada, quien la importó ve el valor nuevo. Pero no puede
asignarle otro: desde fuera es de solo lectura.

### Reunir módulos

Cuando varias piezas se usan juntas, es común tener un archivo que las reexporta para que
quien las use haga un solo `import`:

```js
export { normalizarTitulo } from './titulos.js';
```

Eso pasa la exportación tal cual, sin copiarla. Lo practicas en el ejercicio 2.

### Importar JSON

Un archivo `.json` se puede importar directamente, pero hay que decirle a Node que es JSON con
`with { type: 'json' }` (un **atributo de importación**). Es una medida de seguridad: evita que
un archivo que esperabas que fuera datos se ejecute como código.

## Errores comunes

**`Error [ERR_MODULE_NOT_FOUND]: Cannot find module '/…/modulos/matematicas' imported from
/…/01-importar.js`.** Te faltó la extensión: escribe `'./modulos/matematicas.js'`. Node
incluso sugiere la corrección en la línea `Did you mean to import "./modulos/matematicas.js"?`.
Si la ruta sí trae extensión, revisa que la carpeta y el nombre estén bien escritos.

**`Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'modulos' imported from …`.** Olvidaste
el `./`. Sin él, Node busca un paquete instalado llamado `modulos`.

**`SyntaxError: The requested module './solucion.js' does not provide an export named
'sumar'`.** El otro archivo no exporta ese nombre. Revisa que tenga `export`, que el nombre
sea idéntico (mayúsculas incluidas) y que no estés usando llaves para algo que se exportó con
`export default`.

**`TypeError [ERR_IMPORT_ATTRIBUTE_MISSING]: Module "file:///…/package.json" needs an import
attribute of "type: json"`.** Al importar un JSON falta `with { type: 'json' }`.

**`TypeError: Assignment to constant variable.`** Intentaste asignar un valor a algo
importado. Las importaciones son de solo lectura; si necesitas cambiarlo, exporta una función
que lo haga (como `registrarVisita()`).

<Aside type="caution" title="Importaciones circulares">
  Si `a.js` importa `b.js` y `b.js` importa `a.js`, alguno de los dos puede usar algo que
  todavía no se evalúa y recibir un `ReferenceError`. Si te pasa, saca lo que comparten a un
  tercer archivo que ambos importen.
</Aside>
